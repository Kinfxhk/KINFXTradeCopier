# 持倉一致性與成交價偏差（只讀標示已接上，不是驗收）

P0 只讀徽章已接到「監察」表格的「偏差」欄；門檻在「設定」分頁的「本次工作階段」（數量／均價差、可設定 ticks 門檻、斷線與過期顯示破折號）。這不是驗收：不構成交易授權，不把 Demo／Prop 標成 ready，不關閉 #3／#4／#7／#9，也不改變 Start／Flatten 封鎖。此文件仍不可計入完成度。目前候選版本仍未通過交易驗收；預設版本保留交易封鎖，funded／實盤帳戶不在範圍內。

## 目的

讓使用者在同一個 Trade Copier 視窗內確認各帳戶是否依照設定跟隨，而不是為了讓數字看起來一致而額外交易。

「一致」必須拆開：

- **合約與方向**：跟隨同一合約，方向依既定鏡像規則一致。
- **數量**：依各帳戶原有 Ratio、Max 和整數配額比較，不可把不同 Ratio 的帳戶強制改為同一手數。
- **委託價格**：限價／停損委託可以沿用 Leader 的指定價格；相同委託價格不代表相同成交。
- **成交均價**：各帳戶有獨立成交，延遲、排隊與滑價會造成差異。市價複製不可保證相同成交價；限價也不能保證每戶成交或均價相同。

## 第一階段：只讀可觀測性

在現有 Copy 表格整合，不另開視窗：

1. 顯示實際合約、方向、帶符號數量、成交均價。
2. 顯示相對 Leader 的均價差（ticks），並明確區分純價差與對買／賣方向不利的滑價。
3. 持倉狀態區分「等待回報」「數量一致」「數量偏離」「成交價偏差」「資料不可用」。價格偏差不是數量偏離。
4. 僅比較已確認的同合約、同方向、可比持倉；平倉／斷線／缺失均價／無效 tick size／Leader 無持倉時顯示破折號，不製造零值。
5. 非同步成交與 Position 回報之間，以 Leader 證據時間起算的回報寬限避免短暫延遲造成假警報。各帳戶的證據版本只記該帳戶自己的變動次數，不能拿來和另一帳戶比較。過期資料不標成一致。
6. 使用者自選價格偏差警告門檻；超過門檻只標示與通知。不得把視覺警告當成已證明需要平倉或補單。

新增平台讀取前須反射核實已安裝 NT8 的 Position 均價與 Instrument tick size 契約。數值在 UI／讀取邊界取得，回報不讀取 WPF 控制項。測試涵蓋多／空、不同 Ratio、未知資料、失效 tick size、回報延遲、斷線與復原，並以 mutant 證明新增判定確實被測到。

## 第二階段：可選的入場價格政策（另行設計與授權）

可評估「相同限價」或「限制追價範圍」，但需獨立覆核訂單生命週期、取消確認、未成交期限、部分成交、Leader 先平倉與風控衝突。

必須明示取捨：不追價會造成部分帳戶沒有成交；相同限價是價格政策，不是同步成交承諾。此模式不是第一階段必要功能，亦不可偷偷把 Leader 市價單改為限價單。

## 禁止的自動修正

- 不為了對齊均價而自動平倉再入場、加倉攤平或反覆追價。
- 不補回斷線期間漏掉的交易。
- 不接管未知／手動持倉，不清除風控鎖或未解決成交證據。
- 不用表格中的零持倉宣告復原完成；#9 的明確 reconciliation 仍是獨立安全關卡。
- 不把「同方向／數量一致」宣傳為「所有帳戶同價成交」。

第一階段完成須有離線數值／UI 測試、獨立覆核、真 NinjaTrader 上的已授權模擬帳戶讀取證據及逐狀態回讀。第二階段若涉及下單，須另外完成精確範圍授權與真機交易驗收。兩階段均未完成前，本文件不得計入完成度或解除封鎖。
